# 1757 — SPlanner S8: tkt adapter — read + create

**Commits:** b0b5f42 (backend), + frontend item actions, + launchd node fix · **Date:** 2026-06-06

## What changed
- `apps/splanner/connectors/tkt.py` (new) — read side polls linked items' tickets via read-only sqlite on `~/.backlog/backlog.db` (no subprocess); status diff updates the item and emits a structured RawSignal (`kind=win` on done, else note); create side shells out to the `tkt` CLI and parses the new id
- `apps/splanner/connectors/__init__.py` — RawSignal gains optional `kind`/`item_id`; generic poll ingestion honors them (structured signals skip AI classify and link directly; calendar signals unchanged)
- `apps/splanner/routes.py` — POST `/api/items/{id}/create-ticket` (work-context only → 400 otherwise, 409 if already linked, 502 on CLI failure)
- Frontend — work-context item rows get "Create tkt" button / `#id` chip on `ProjectDetailPage`

## Key decisions
- Read = direct read-only sqlite (fast, no parsing); create = CLI (respects tkt business logic)
- Status mapping: open/backlog/deferred→todo, in_progress→doing, done→done, cancelled→todo; signal emitted only when mapped status differs from item status (self-deduping; source_ref carries `tid:status:updated_at`)
- tkt CLI subprocess env prepends `TKT_BIN`'s parent to PATH — `#!/usr/bin/env node` shebang fails under launchd otherwise (second launchd-PATH bug after S5's; both found by live smoke)
