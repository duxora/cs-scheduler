# 1754 — SPlanner S5: async AI classify worker on check-in create

**Commits:** 23fd983 (backend), 31702fa (frontend), 6969895 (launchd fix) · **Date:** 2026-06-06

## What changed
- `apps/splanner/classify.py` (new) — `classify_checkin(id)`: renders the non-archived project/objective/item tree, runs headless `claude -p` (60s timeout, strict-JSON contract `{kind, suggested_link:{level,id}|null, confidence}`), validates enums + tree membership, updates kind/ai_classified/suggested_* on success
- `apps/splanner/db.py` — `suggested_level`/`suggested_id` columns on checkins + idempotent `ALTER TABLE` migration for existing DBs (schema is `CREATE TABLE IF NOT EXISTS`)
- `apps/splanner/routes.py` — POST `/api/checkins` with omitted `kind` inserts as `note` and queues background classify (FastAPI BackgroundTasks); explicit kind unchanged, no subprocess. New PATCH `/api/checkins/{id}` for corrections — any patch consumes (clears) the suggestion
- Frontend — composer defaults to "Auto (AI)" (omits kind, polls stream ≤90s until classified); stream renders AI suggestion chip with Accept (PATCH suggested ids) / Change (scope picker) controls

## Key decisions
- **Async over sync classify** (user call): POST returns immediately, no LLM latency/coupling in the request path; worker updates the row
- **Suggestions persisted in dedicated columns**, never written to real link columns (project_id/objective_id/item_id hold confirmed links only) — async means the suggestion can't ride the POST response and must survive refresh
- Accept = frontend PATCHes the suggested ids explicitly; no separate accept endpoint
- ANY worker failure (timeout, malformed JSON, invalid enum/dangling id, missing binary) leaves the row untouched — classification never blocks or corrupts the insert
- `claude` binary resolved via `shutil.which` + `~/.local/bin/claude` fallback — launchd PATH lacks shell locations (found via live failure on check-in #2)
