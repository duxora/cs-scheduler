## What changed
- `apps/splanner/connectors/__init__.py` (new) — `Connector` protocol per spec, `RawSignal` dataclass, registry (`register`/`get_connector`/`list_connectors`), `ConnectorNotConfigured`
- `apps/splanner/connectors/calendar.py` (new) — Google Calendar adapter over raw REST via httpx (no google client libs): refresh-token → access token, events list with timeMin/singleEvents; skips cancelled/summary-less events; credentials at `DATA_DIR/splanner-google.json`
- `apps/splanner/routes.py` — POST `/api/connectors/{name}/poll` (dedup by (source, source_ref), inserts new signals as `note` check-ins + queues S5 classify per row; 503 unconfigured, 404 unknown), GET `/api/connectors` status
- Frontend — "Sources" row on project detail: connector chips (configured / needs credentials), Sync now → poll + stream refetch with "+N check-ins" note

## Key decisions
- No new dependencies — httpx REST instead of google-api-python-client
- No schema changes — `since` derived from MAX(created_at) of calendar-sourced check-ins (fallback 7d); dedup via (source, source_ref) existence check makes coarse `since` safe
- Manual entry is NOT a registered connector (spec: bypasses poll)
- Connector signals enter the existing S5 pipeline unchanged: insert as note → async classify → suggestion
