# 1755 — SPlanner S6: weekly digest end-to-end (draft → review → approve)

**Commits:** 80f71c9 (backend), + frontend digest view · **Date:** 2026-06-06

## What changed
- `apps/splanner/digest.py` (new) — `draft_digest(week_start)`: gathers the week's check-ins + server-computed KPI deltas, runs headless `claude -p` (120s, reuses `CLAUDE_BIN`/`_extract_json_object` from classify.py), validates `{narrative_md, risks[], nudges[], focus[]}`; invalid entries dropped, any failure returns None
- `apps/splanner/routes.py` — POST `/api/digest/draft` (synchronous, upsert by Monday-normalized week_start, resets state to drafted, 502 + no row on AI failure), GET `/api/digest/latest`, GET `/api/digests`, PATCH `/api/digest/{id}` (narrative/focus edits; drafted→needs_review; 409 on approved), POST `/api/digest/{id}/approve`
- Frontend — `DigestPage` (week ◀▶, lifecycle badge, Draft/Re-draft spinner, Approve & save, KPI delta strip with ▲▼ arrows, inline-editable narrative, focus accept checkboxes), `DigestPanels` (severity-ranked risks with evidence counts, nudges navigating to projects), dashboard header link

## Key decisions
- **kpi_deltas computed server-side**, not by the AI — baseline = most recent prior digest's stored snapshot (no metric history table; self-bootstrapping, first week `prev_current=null`). AI gets the numbers as input context only; prose from AI, numbers from code
- **Draft is synchronous** (user-initiated with spinner) — unlike S5's fire-and-forget classify; re-draft overwrites the week's row and resets to drafted
- PATCH on an approved digest → 409; approved digests render read-only
